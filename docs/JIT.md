# StikDebug и JIT

Podium7 компилирует MOVZ/MOVK, NOP и ADD/SUB immediate без флагов и SP в нативные ARM64-блоки. Остальные инструкции выполняет интерпретатор. Это ускоритель Swift CPU; полный QEMU TCG пока не встроен в IPA.

Один заранее выделенный пул хранит неизменяемые блоки. При заполнении CPU переходит на интерпретатор. Кэш проверяет изменения гостевого кода. Гостевые инструкции не исполняются напрямую на хосте: транслируется только разрешённая регистровая арифметика, доступ к памяти остаётся в эмуляторе.

## На телефоне

1. Подписать IPA с `get-task-allow = true`, используя App/Podium7.entitlements. Проверяется право установленного приложения.
2. Настроить StikDebug и включить Developer Mode.
3. Нажать «Включить JIT в StikDebug», подключить отладчик и вернуться в Podium7.
4. Дождаться «JIT работает: нативный ARM64-тест пройден». Открытие URL или флаг отладчика сами по себе не означают готовность.
5. «Проверить ARM64» показывает число инструкций, реально выполненных JIT.

При наличии TXM/SPTM приложение выбирает единственный фиксированный universal.js. Реализованы brk #0xf00d, подготовка RX-региона, RW-алиас и detach. Без TXM скрипт не запрашивается. Неизвестное состояние TXM возвращает ошибку. После detach новые области не выделяются.

В LiveContainer требуется «Use LiveContainer's Bundle ID». Встроенного StikJIT/helper extension нет; используется внешнее приложение StikDebug.

## Проверка

На Apple Silicon Mac нативные блоки сопоставлены с интерпретатором по регистрам, PC и счётчику инструкций. Проверены 32-битная арифметика, изменённый код, бюджет выполнения, неподдерживаемые инструкции и заполнение пула. Собрана iPhone IPA и проверены её параметры StikDebug.

Подключение StikDebug, TXM-протокол и практическая скорость на физическом iPhone пока не проверены. Гостевая iOS ещё не загружается полностью.

Официальная инструкция: https://github.com/StikDebug/StikJIT/blob/main/INTEGRATION.md
